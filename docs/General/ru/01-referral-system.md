# General — Реферальная система

Реферальная система позволяет стримерам и партнёрам (агентствам) привлекать новых стримеров через уникальные ссылки. Привязка реферала к пригласившему происходит при заполнении профиля после регистрации.

---

## Типы реферальных ссылок

| Тип | Маршрут | Пример ссылки |
|---|---|---|
| Стример → стример | `/ref/:token` или `/:locale/ref/:token` | `.../en/ref/tw3yvg...?utm_source=referral&utm_medium=1372&utm_label=yuriysokol` |
| Партнёр → стример | `/partner/ref/:token` или `/:locale/partner/ref/:token` | `.../ru/partner/ref/30iys9g...?utm_source=uplify&utm_medium=partner&utm_campaign=1321` |

Обе формы поддерживают опциональный `/:locale/` префикс в URL — для локализованных приглашений. Логика обработки при этом одинакова.

---

## Сценарий 1: Переход незарегистрированного пользователя

```
Пользователь открывает ссылку /ref/:token?utm_*=...
  ↓
Auth.vue — определяет, что маршрут реферальный
  ↓
setRegisterParams(route.query)  — сохраняет UTM-параметры и promo в localStorage
setReferral(token, utm_campaign) — сохраняет реферальный токен в localStorage
  ↓
Редирект на страницу входа (SigninStreamer)
  ↓
Пользователь регистрируется / входит
  ↓
Если профиль не заполнен → редирект на StreamerSettings
  ↓
Пользователь заполняет профиль и сабмитит
  ↓
POST streamer/profile { referral, utm, promo, ... }
  ↓
Очистка registration-params из localStorage
  ↓
Редирект в приложение
```

---

## Сценарий 2: Переход авторизованного пользователя

Если стример уже вошёл в аккаунт и открывает реферальную ссылку `/ref/:token`, маршрутизатор модуля Streamer перехватывает запрос и показывает страницу `ReferralCheck` — экран с анимацией и кнопкой «Перейти в приложение».

Токен при этом **не сохраняется**: пользователь уже зарегистрирован, реферал к нему не применяется.

---

## Хранение токена в localStorage

Реферальный токен хранится под ключом `referral`:

```json
{
  "createdAt": 1712000000000,
  "value": "tw3yvgcor63sypxzksmgbtsb",
  "partnerId": "1321"
}
```

| Поле | Описание |
|---|---|
| `value` | Токен из URL-параметра `:token` |
| `createdAt` | Время сохранения (timestamp) |
| `partnerId` | `utm_campaign` из URL — ID партнёра, если ссылка от агентства |

**Правила:**

- **TTL — 7 дней.** При попытке прочитать просроченный токен он удаляется и возвращается `null`.
- **First-write-wins.** Если валидный токен уже есть, новый не записывается. Повторные переходы по разным ссылкам до регистрации не перезаписывают первый токен.

---

## Хранение регистрационных параметров

UTM-параметры и промокод хранятся отдельно под ключом `registration-params`:

```json
{
  "promo": "SUMMER24",
  "utm_source": "referral",
  "utm_medium": "1372"
}
```

- Сохраняются из `route.query` при любом переходе (не только реферальном).
- Не имеют TTL — живут до первого успешного заполнения профиля.
- Удаляются после `POST streamer/profile` с успешным ответом.

---

## Передача параметров на бэкенд

При заполнении профиля (`StreamerSettings`) данные из обоих хранилищ объединяются в payload:

| Поле в запросе | Источник | Описание |
|---|---|---|
| `referral` | `localStorage['referral'].value` | Реферальный токен |
| `utm` | `localStorage['registration-params'].utm_*` | UTM-параметры как объект |
| `promo` | `localStorage['registration-params'].promo` | Промокод |

Запрос: `POST streamer/profile`

Если реферального токена в localStorage нет (истёк, не было перехода по ссылке) — поле `referral` в payload не включается.

> `registration-params` очищается после сабмита. Реферальный токен (`referral`) остаётся в localStorage до истечения 7-дневного TTL — он не удаляется явно после регистрации.

---

## Источники реферальных ссылок

Ссылки генерирует бэкенд и отдаёт через API:

| Контекст | Эндпоинт | Поле |
|---|---|---|
| Страница «Рефералы» стримера | `GET streamer/referral` | `link` |
| Dashboard агентства | `GET partner/referral` | `link` |

На фронтенде ссылки отображаются с кнопкой копирования. Стример также может поделиться ссылкой через нативный `navigator.share` (Facebook / Twitter).
