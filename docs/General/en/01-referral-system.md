# General — Referral System

The referral system lets streamers and partners (agencies) invite new streamers via unique links. The referral attribution happens when the invited user fills out their profile after registration.

---

## Referral Link Types

| Type | Route | Example |
|---|---|---|
| Streamer → Streamer | `/ref/:token` or `/:locale/ref/:token` | `.../en/ref/tw3yvg...?utm_source=referral&utm_medium=1372&utm_label=yuriysokol` |
| Partner → Streamer | `/partner/ref/:token` or `/:locale/partner/ref/:token` | `.../ru/partner/ref/30iys9g...?utm_source=uplify&utm_medium=partner&utm_campaign=1321` |

Both types support an optional `/:locale/` prefix for localized invitations. The handling logic is identical either way.

---

## Scenario 1: Unauthenticated User Follows a Referral Link

```
User opens /ref/:token?utm_*=...
  ↓
Auth.vue — detects a referral route
  ↓
setRegisterParams(route.query)   — saves UTM params and promo to localStorage
setReferral(token, utm_campaign) — saves referral token to localStorage
  ↓
Redirect to sign-in page (SigninStreamer)
  ↓
User registers / logs in
  ↓
If profile is not filled → redirect to StreamerSettings
  ↓
User fills out profile and submits
  ↓
POST streamer/profile { referral, utm, promo, ... }
  ↓
registration-params cleared from localStorage
  ↓
Redirect into the app
```

---

## Scenario 2: Authenticated User Follows a Referral Link

If a streamer is already logged in and opens `/ref/:token`, the Streamer module router intercepts the request and renders the `ReferralCheck` page — a screen with an animation and a "Go to app" button.

The token is **not saved** in this case: the user is already registered, so the referral does not apply.

---

## Token Storage in localStorage

The referral token is stored under the key `referral`:

```json
{
  "createdAt": 1712000000000,
  "value": "tw3yvgcor63sypxzksmgbtsb",
  "partnerId": "1321"
}
```

| Field | Description |
|---|---|
| `value` | Token from the `:token` URL segment |
| `createdAt` | Save timestamp (ms) |
| `partnerId` | `utm_campaign` from URL — partner/agency ID |

**Rules:**

- **TTL — 7 days.** Reading an expired token removes it and returns `null`.
- **First-write-wins.** If a valid token already exists, a new one is not written. Following multiple referral links before registering keeps the first captured token.

---

## Registration Params Storage

UTM parameters and promo code are stored separately under `registration-params`:

```json
{
  "promo": "SUMMER24",
  "utm_source": "referral",
  "utm_medium": "1372"
}
```

- Populated from `route.query` on any navigation (not only referral routes).
- No TTL — persist until the first successful profile submission.
- Cleared after a successful `POST streamer/profile` response.

---

## Passing Parameters to the Backend

When the user submits the profile form (`StreamerSettings`), data from both storage entries is merged into the request payload:

| Request field | Source | Description |
|---|---|---|
| `referral` | `localStorage['referral'].value` | Referral token |
| `utm` | `localStorage['registration-params'].utm_*` | UTM parameters as an object |
| `promo` | `localStorage['registration-params'].promo` | Promo code |

Request: `POST streamer/profile`

If no referral token is in localStorage (expired or user never clicked a referral link), the `referral` field is omitted from the payload.

> `registration-params` is cleared after submission. The referral token (`referral`) stays in localStorage until the 7-day TTL expires — it is not explicitly removed after registration.

---

## Referral Link Sources

Links are generated by the backend and returned via API:

| Context | Endpoint | Field |
|---|---|---|
| Streamer "Referrals" page | `GET streamer/referral` | `link` |
| Agency dashboard | `GET partner/referral` | `link` |

On the frontend, links are displayed with a copy button. Streamers can also share via the native `navigator.share` (Facebook / Twitter).
