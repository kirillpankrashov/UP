# FormAdset — Создание и редактирование

Поведение экрана с точки зрения пользователя: шаги, кнопки, валидация, сохранение и выход.

---

## Создание адсета

1. Пользователь переходит к созданию адсета из экрана кампании. **Тип кампании** определяется из slug кампании в URL — от него зависит, какая форма откроется.
2. Параллельно загружаются **словарь кампаний** для нужного типа, **список рекламодателей** и **структура кампании** (для боковой навигации).
3. Пока идёт загрузка, отображается скелетон формы.
4. После загрузки открывается пустая форма настроек адсета (конкретная секция зависит от типа кампании).
5. Основное действие — **«Сохранить»**. После успешного сохранения пользователь **не возвращается в список** — происходит редирект на экран **редактирования** только что созданного адсета.

---

## Редактирование адсета

1. При открытии загружаются данные адсета (`fetchAdset`) и словарь кампаний. Тип кампании определяется из ответа API.
2. Если загрузка **не удалась** — отображается сообщение об ошибке с кнопкой **«Повторить»**. Повторная попытка сбрасывает флаги ошибок и запускает загрузку заново.
3. В верхней части формы может быть **переключатель статуса** (вкл./выкл.). Изменение статуса вызывает `changeStatus` на уровне кампании, затем обновляет адсет.

---

## Дублирование

В режиме редактирования доступна кнопка **«Дублировать»**:

1. Текущий адсет сохраняется в стор (`formAdsetStore.adset`).
2. Происходит навигация на экран **создания** адсета в той же кампании.
3. Форма создания подхватывает данные из стора для предзаполнения.

> Фактическое поведение предзаполнения зависит от того, как конкретная секция формы обрабатывает данные из стора при инициализации. Рекомендуется проверять на стенде.

---

## Сохранение и валидация

- Во время выполнения запроса форма **блокируется** для предотвращения повторной отправки.
- Если **обязательные поля** не заполнены, сохранение не проходит: проблемные поля подсвечиваются, экран прокручивается к первой ошибке.
- После успешного сохранения показывается подтверждение.

---

## Несохранённые изменения

Если пользователь изменил данные по сравнению с пустым черновиком (создание) или последней сохранённой версией (редактирование), при попытке уйти с экрана может появиться диалог подтверждения.

---

## Куда ведёт «Назад» / закрытие

- Маршрут возврата зависит от типа кампании и режима (создание / редактирование).
- При **создании** — возврат к экрану кампании или списку кампаний соответствующего типа.
- При **редактировании** — возврат определяется дочерней формой (метод `closeAndReturnRoute`).
