# FormCampaign — Обзор

## Что это

Экран в кабинете партнёра, на котором **создают новую кампанию** или **редактируют существующую**. Оформление согласовано с другими экранами вокруг кампаний: заголовок, при редактировании — боковая навигация по структуре кампании (если она загрузилась).

Подробнее про списки кампаний, вкладки и таблицы см. [Кампании — обзор](../../Campaigns/ru/01-overview.md).

---

## Основные идеи

- Поддерживаются **все типы кампаний** — те же, что в разделе «Кампании» (см. [типы кампаний](../../Campaigns/ru/02-campaign-types.md)).
- **Новая кампания** обычно проходит в **два шага**: сначала выбор типа, затем заполнение настроек и сохранение.
- **Редактирование** открывается сразу на шаге настроек: данные подтягиваются с сервера при открытии карточки.

---

## Структура экрана

```
Заголовок (название кампании или запасной текст)
 ├── При создании: либо выбор типа, либо форма настроек
 ├── При редактировании: форма настроек
 └── Снизу — панель действий: «Назад» / «Отмена» и «Далее» или «Сохранить»
```

На шаге выбора типа отдельным списком могут отображаться типы со статусом «скоро». Состав карточек и текст на них приходят с бэкенда (см. раздел «Словари с бэкенда» в этом файле ниже).

## Словари с бэкенда {#form-campaign-dictionaries}

Экран опирается на два источника справочников (оба — ответы API, наполнение задаётся на стороне сервера).

### Общий словарь кабинета

Загружается для **локали** интерфейса партнёра (как и на других экранах кабинета). На форме кампании из него используются:

| Поле / блок на экране | Поле в `dictStore` | Что даёт бэкенд |
|---|---|---|
| **Категория** (в настройках кампании) | `all.campaignsCategories` | список категорий с подписями (и служебными признаками, например dark market) |
| **Часовой пояс** (если поле показано для типа) | `all.timeZones` | список часовых поясов с подписями |

### Словарь кампаний

Запрашивается **при открытии экрана** формы. В запросе учитываются **локаль** и **тип кампании в контексте** (из ссылки при создании или из открытой карточки при редактировании). На этой форме из ответа используются:

| Поле / блок на экране | Поле в `dictStore` | Что даёт бэкенд |
|---|---|---|
| **Шаг выбора типа** (только **создание** кампании) | `campaigns.types` | список типов: идентификатор типа, **название и описание** на карточке, иконка, признак **можно ли выбрать для создания**; невыбираемые типы показываются в блоке «скоро» |
| **Холдинг рекламодателя** | `campaigns.holdings` | холдинги (название, описание, логотип и т.д.) |
| **Медиа агентство** | `campaigns.mediaAgencies` | список медиа-агентств с названиями |
| **Партнёрские сети** (если блок есть у типа) | `campaigns.affiliateNetworks` | сети с названиями и данными о валюте |

> **Рекламодатель** в выпадающем списке **не** из словаря кампаний: список приходит **отдельным запросом** и сужается по выбранному холдингу.

В том же ответе словаря кампаний нередко приходят платформы, форматы креативов и другие сущности **для других экранов** (группы, креативы). Для **формы кампании** они не подставляются в поля — это ожидаемо.

## Поток данных

Единый Pinia-стор `useFormCampaignStore` хранит **текущий тип кампании**, **шаг мастера** (выбор типа или настройки), загруженную **кампанию** и **структуру** для боковой панели при редактировании, плюс флаги загрузки и признак ошибки загрузки.

При редактировании стор запрашивает структуру и данные кампании; при сохранении вызывает **создание** или **обновление** через API, выбранный по типу кампании. После ухода с экрана состояние стора очищается.

**Кеширование:** ответы запросов на **чтение** кампании и её структуры (для боковой панели) на клиенте хранятся **до часа**, по аналогии со списками в разделе [Кампании](../../Campaigns/ru/01-overview.md). Запросы **создания** и **обновления** сбрасывают связанный кеш (данные карточки, структура и связанные сущности партнёрского кабинета для этого типа), чтобы после сохранения не показывались устаревшие ответы.
